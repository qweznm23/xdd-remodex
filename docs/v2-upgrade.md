# 从 fix73 迁移到 fix74

fix74 Android 使用 Remodex 安全协议 V2。先将 APK 下载到手机，把同版服务端包下载到各台电脑。通过旧设备下载 APK 的用户请在切换前完成下载。fix74 客户端与 V2 桥接需要配套使用。

1. 选一台测试桥接，记下原服务端程序目录、运行账户、启动命令、环境配置、配对状态目录及中继地址。新包解压到单独目录。首次部署的中继、桥接启动参数可参考[服务端指南](server-install.md)。
2. 在维护时段切换这台机器的桥接和中继程序，沿用原运行账户、状态目录和端口。编号授权库、Codex 当前凭据和配对文件应继续指向原位置。使用 systemd 模板时，核对启动命令的实际路径。先确认手机可访问原地址的 HTTP 健康检查。
3. 在测试手机上覆盖安装同签名的 fix74，打开原设备，检查原会话、发送消息、断线重连和补历史，然后逐台切换其余桥接。仍在 fix73 的服务端需要 V1 手机。继续使用自选 TCP 端口和原来的 WS/WSS 方案。
4. 如需恢复，切回旧的桥接和中继程序目录，沿用当前运行数据。原 fix73 APK 的 versionCode 为 89，低于 fix74 的 90。另备的 `remodex-0.1.7-ws-fix73-recovery.apk` 从 `46136e1` 的 Android 源码构建，只调整版本名和 versionCode（91）。它用于覆盖 fix74 并连接旧桥接。用过恢复包的设备，下次升级请使用 versionCode 高于 91 的正式包。Linux 服务端与 Android 真机已验证沿用原配对及切网重连。V1 恢复包已核验签名和版本，真机回退仍待演练。
